# 升级与版本维护

## 升级前

备份整个安装目录中需要保留的 `.env`、`secrets/`、`data/`、`components/`、`releases/`、小雅数据和自定义配置。停止会写入这些数据的外部业务，并确认有可用的回滚副本。不要把备份上传到公开仓库。

## 重新运行安装器

在原安装目录重新运行公开 v2.2.0 安装器，选择菜单 `1` 的安装或升级。安装器会刷新公开模板和匹配架构的制品；正常升级不应删除已有 secrets、数据库或用户媒体数据。安装完成后从菜单 `5` 查看状态，并检查：

```bash
curl -fsS http://127.0.0.1:18080/api/health
docker ps --filter name=xymedia
```

可使用与安装相同的 `XYMEDIA_MIRROR` 下载镜像；不设置时从公开 GitHub Release 直连。镜像不可用时取消变量重试。

## 版本和边界

安装器当前默认固定 v2.2.0，不建议使用移动的 `latest` 作为生产版本。未来若管理员明确提供兼容的 `XYMEDIA_CATALOG_URL` 和 `XYMEDIA_RELEASE_BASE`，两者应指向同一版本的公开资产，并保留对应备份。

升级失败时不要删除旧的 `releases/`、数据库或 secrets。保留安装日志的脱敏副本，确认旧容器和数据仍在，再按 [恢复](recovery.md) 操作。数据迁移、版本回退和跨主机迁移不是“重新运行安装器”可以自动解决的事项。
